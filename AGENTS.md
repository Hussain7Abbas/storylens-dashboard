# Story Lens dashboard instructions

Standalone public repository, also pinned in the Story Lens umbrella at `apps/dashboard`. It is the admin dashboard for the Story Lens API: dashboard users, roles and permissions, novels, keyword translations, lenses and billing requests, and settings (configs and AI). Use Bun and Biome; `make help` lists commands. Umbrella guide: `docs/dashboard.md`. The repository, domain, web root and server checkout are named `storylens-dashboard`.

## Stack and structure

- Vite + React 19 single-page app, React Router, TanStack Query and Axios; Tailwind v4 with the Ink & Iris tokens in `src/styles/globals.css`. Nginx serves the static `dist/` build; there is no Node server in production.
- `src/api/generated/` is the Orval client for the dashboard API only (`Admin: …` tags, `/api/admin`). Never edit it; regenerate with `make orval` against a running local backend (`ORVAL_API_URL`, default `http://localhost:3030`; the spec is off in production) and commit the output. `orval.config.ts` drops the `ApiAdmin` prefix from operation names (`getUsersById`). `src/api/axios-instance.ts` is the mutator: it adds the bearer token and signs out on 401.
- `src/lib/session.ts` keeps the session token in `localStorage` (`storylens-dashboard-token`); `src/lib/auth.tsx` loads `/api/admin/auth/me` and exposes `can(permission)`. `src/lib/permissions.ts` lists the dashboard permission keys (`METHOD /api/admin/...`), which must match the backend routes.
- `src/components/ui/` holds shared controls (buttons, fields, native dialogs, confirm dialogs, toasts, pagination, page states); `src/components/layout/app-shell.tsx` is the sidebar layout; `src/pages/` has one file per screen.
- Novel and keyword names are translated (`nameAr`/`nameEn`; novels also `descriptionAr`/`descriptionEn`). The dashboard edits both languages; show them with `bothNames` from `src/lib/translation.ts`.
- Keyword and alias forms expose `fuzzyMatchArabicCharacters` below Full word match when either name contains Arabic letters. Preserve its stored value on edits and default new records to `true`; the extension applies the matching behavior on pages. The API stores keyword and alias names without Arabic diacritics (حركات), so a saved name can come back shorter than typed.
- Lenses: show prices and balances with `LensCoin`/`LensPrice` (`src/components/ui/lens-coin.tsx`) and money through `src/lib/money.ts` (integer micro-dollars and cents, the backend's rounding). Gifts, adjustments and history are dialogs in `src/components/users/lens-dialogs.tsx`; **Billing requests** is `src/pages/billing-requests.tsx`.
- `LensCoin` keeps the original full/small/mono SVG fixed and adds three CSS sparkles through `src/lib/lens-coin/LensCoinSparkles.tsx`. They brighten at 300 ms offsets (900 ms per sparkle), using theme iris or `currentColor` for mono, with fixed layout and decorative accessibility. Containing-control hover/focus pauses the sparkle opacity; reduced motion and forced colors hide the decorations. Mirror the component and global styles from umbrella `docs/branding/lens-coin/`; no animation player, timers or remote assets. `tests/lens-motion.spec.ts` checks staggered lighting, static artwork and reduced-motion changes.
- **Settings** (`src/pages/settings.tsx`, `/settings?tab=configs|ai`) hosts `ConfigsPanel` (`src/pages/configs.tsx`) and `AiSettingsPanel` (`src/components/settings/ai-settings.tsx`); `/configs` and `/ai-pricing` redirect to it. The AI tab's model pickers read `GET /api/admin/ai-models/` and save the `AI_Text_Model`/`AI_Image_Model` configs; cost estimates live in `src/lib/ai-cost.ts` (typical tokens per feature, OpenRouter fee, healthy margin). Keep those profiles in step with the backend features and warn before saving a model that loses money.
- **Match translations** (`src/pages/match-translations.tsx`, `/translations`) lists a novel's keywords named in only one language (`GET /api/admin/keywords/?untranslated=true`), 50 per page. It pairs with the Story Lens desktop client through `src/lib/desktop-client.ts` (port, defaulting to the client's 43127, pairing token, model and effort in `localStorage` `storylens-dashboard-desktop-client`; the client only accepts this site's production and `localhost:3040` origins) and when the admin clicks **Suggest page** (**Re-suggest page** once the page has suggestions; nothing runs automatically) asks it, once per target language, for the missing names and for matches among keywords named only in the other language (`src/lib/translation-prompt.ts`). A row's source and target language come from the name's script (`singleName`/`namesByScript` in `src/lib/translation.ts`), because older keywords keep English names in `nameAr`; saving a translation sends both names so a misfiled name moves to its column, and linking refiles both keywords first. Each row has an editable translation and Link / Alias of / Version of pickers (`components/ui/keyword-picker.tsx`) that fuzzy-match (`src/lib/fuzzy.ts`) the novel's keywords in both languages, loaded once per novel by `src/lib/novel-keywords.ts` from `GET /api/admin/novels/:id/keywords` (the profile's query, so the role needs that permission too). `mode="link"` offers keywords and every alias as its own result (`PickedKeyword.kind`); saving a link to an alias calls `POST /keywords/:id/link-alias` after checking the alias has no other name in the row's language. `mode="parent"` (Alias of, Version of) offers main keywords only, matched by their aliases too. Versions are never offered. Aliases are named by `nameAr`/`nameEn` only (the API dropped `name`); the profile's alias form edits both names like the keyword form. Choosing one relation disables the others and the translation. AI link candidates come from the same list. A run keeps an `AbortController`: **Cancel suggesting**, a page or novel change, or leaving the page aborts the request, and the desktop client then stops the model. A new AI run replaces prior AI drafts but never overwrites an admin-edited row. **Save** applies the translation (`PUT`) or the chosen relation (`POST …/link`, `…/alias`, `…/version`); **Ignore** hides the row until reload. Row checkboxes drive **Save selected** / **Ignore selected**; selections belong to one page, so changing page or novel asks before clearing them. The Nginx CSP allows `connect-src http://127.0.0.1:*` for the client.
- **Novel profile** (`src/pages/novel-profile.tsx`, `/novels/:id`, opened from a novels-table row) shows the novel and `components/keywords/characters-section.tsx`: every keyword from `GET /api/admin/novels/:id/keywords`, filtered and paged in the browser. The AR/EN switch, a full search and one filter per column (image, character, languages, category, nature, description, match, added by) live in the URL (`useSearchState`). Versions (when more than one) and aliases are nested rows under their keyword, as in the extension; empty values fall back to the base version's and show in italics. Row actions open `components/keywords/keyword-forms.tsx` (`KeywordForm` creates a keyword with `POST /keywords/` from **New keyword**, or saves names and matching with `PUT /keywords/:id` and the base version with `PUT /keyword-versions/:id`; `AliasForm`; `VersionForm`) or a `ConfirmDialog`; `src/lib/keyword-details.ts` holds the helpers and `refreshKeywords`, which invalidates the profile, keyword and novel queries. `components/ui/image-field.tsx` is the shared image upload used by these forms and the novel form.
- Use strict TypeScript, named exports, no `any`, and no lint-suppression comments.
- Page translators and text-rewriting extensions replace bare text nodes, which makes React's `insertBefore`/`removeChild` crash. Don't render an element that toggles next to bare text, or text that appears and disappears beside siblings; wrap the text in a `<span>`. `Button` already wraps its label (its spinner toggles before it). `tests/dashboard.spec.ts` covers this with `translatePage`.

## Access rules

- The dashboard has sign-in only. Never add registration: dashboard access (`isAdmin` + a dashboard role) is granted from the Users page (`POST`/`PUT /api/admin/users`) or by the backend seed. One account can have reader access (`isUser` + a reader role), dashboard access, or both, with one email, username and password; readers register from the extension and website.
- When enabling reader access in the Users form, default to the `reader` role by slug, even if the API lists `guest` first. Default dashboard access to `super-admin` by slug. If the preferred reader role is missing, require an explicit choice instead of assigning Guest.
- The API enforces every permission. The UI only hides pages and actions: guard routes with `Allow` in `src/app.tsx` and actions with `can(PERMISSIONS…)`, and show `Forbidden` rather than an empty page. When a backend admin route is added or renamed, update `src/lib/permissions.ts`, the generated client and the relevant page.
- A user can't change their own dashboard access or role, delete themselves or remove the last super admin; the API refuses these and the UI does not offer them. The `super-admin` role always holds every admin permission and its list is read-only.

## Design

- Follow `design-system/MASTER.md`, which applies the website's Ink & Iris identity (`storylens-website` `design-system/MASTER.md`) to a dense admin layout. Use the tokens, Inter (self-hosted `@fontsource-variable/inter`), Lucide icons at 1.75 stroke with accessible names on icon-only buttons, visible 3px focus rings, and 44px targets on coarse pointers. Keep light, dark and system themes working, respect reduced motion, and avoid horizontal page scroll at 375px (tables scroll inside their card; a table with no buttons or links would be a scroll area out of keyboard reach, so give it `data-table-stack` and a `data-label` on every cell: it stacks into label and value rows on phones).
- Confirm destructive actions with `ConfirmDialog`, report results with toasts, and keep errors next to the form that caused them.
- The UI UX Pro Max skill is vendored in `.claude/skills/ui-ux-pro-max` (MIT). Query it for new screens; its palette and font suggestions never override Ink & Iris.

## Checks and deployment

- Run `bun run typecheck`, `bun run lint`, `bun run build` and `bun run test` (Playwright + axe against the production build with the API mocked in `tests/fixtures.ts`; set `CHROMIUM_PATH` to use a preinstalled Chromium).
- `tests/live-api.spec.ts` is an opt-in Chromium test of the built dashboard, real local backend and isolated PostgreSQL database. It requires `STORYLENS_E2E_API_URL`, `STORYLENS_E2E_ADMIN_EMAIL` and `STORYLENS_E2E_ADMIN_PASSWORD`; the API URL must be loopback. Build with matching `VITE_API_URL` and run a preview server before the test. See the umbrella dashboard guide.
- Production: https://storylens-dashboard.iscoded.com on the `ssh raseen` server. The checkout is `/srv/storylens-dashboard` on `main`; `make sync` (as root) fast-forwards, builds, atomically swaps `/var/www/storylens-dashboard/current`, installs `deploy/nginx/storylens-dashboard.iscoded.com.conf`, obtains the Let's Encrypt certificate on first run, checks the site and rolls back on failure. The Nginx CSP allows API calls only to `https://storylens-api.iscoded.com`; update it with `VITE_API_URL` (`.env.production`).
- `.github/workflows/deploy.yml` is the only workflow and runs no checks. Pushes to `main` do not deploy. The backend's review-version watcher sends a `backend-deployed` `repository_dispatch` event after its `make sync` succeeds, and a manual dispatch on `main` also works. The workflow then sends `main`'s SHA over SSH, and the server rebuilds the dashboard. The `production` environment secrets are `DEPLOY_HOST` (`root@<ip>`), `DEPLOY_PORT`, `DEPLOY_KNOWN_HOSTS`, `DEPLOY_SSH_KEY` (a dedicated passphrase-protected key) and `DEPLOY_SSH_PASSPHRASE`. The workflow decrypts the runner's copy of the key. On the server that key is restricted to `command="/usr/local/lib/storylens/dashboard-ci-ssh.sh",restrict`, a wrapper installed from `deploy/ci-ssh.sh` that checks the commit is on `main`, refuses a dirty checkout, locks, checks out the commit and runs `make deploy`. Never upload an unrestricted personal SSH key.
- Keep this file, `README.md` and the umbrella `docs/dashboard.md` current with changes.
